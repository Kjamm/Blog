## 프로젝트 개요

pdb2mcsm은 단백질 복합체의 PDB 파일을 mCSM-PPI2에서 분석할 수 있도록 자동으로 전처리하는 오픈소스 프로젝트이다.

단백질 간 상호작용(Protein–Protein Interaction, PPI)을 분석하는 과정에서는 다양한 구조 예측 모델과 분자 동역학 시뮬레이션(Molecular Dynamics Simulation)에서 생성된 구조 데이터를 활용한다.

하지만 이렇게 생성된 데이터가 항상 분석 도구의 입력 형식을 만족하는 것은 아니다.

이러한 데이터 호환성 문제를 해결하고, 반복적인 전처리 작업을 자동화하기 위해 pdb2mcsm을 개발했다.

## 프로젝트 개발 배경

단백질 간 상호작용을 연구할 때 중요한 분석 중 하나는 특정 아미노산 잔기가 단백질의 결합에 얼마나 중요한 역할을 하는지 파악하는 것이다.

특히 FOXO4와 같은 단백질의 결합 부위를 분석하는 연구에서는 결합에 중요한 역할을 하는 잔기, 즉 Hotspot Residue를 탐색하는 과정이 필요하다.

이를 위해 활용할 수 있는 도구 중 하나가 mCSM-PPI2이다.

mCSM-PPI2는 단백질 복합체의 구조적 특징을 활용하는 머신러닝 기반의 분석 도구로, 아미노산 변이가 단백질 간 결합 친화도에 미치는 영향을 예측한다.

하지만 분석 과정에는 예측 모델 자체와는 별개의 문제가 존재한다.

바로 입력 데이터의 품질과 호환성이다.

분자 동역학 시뮬레이션이나 구조 모델링 과정에서 생성된 PDB 파일에는 다음과 같은 문제가 발생할 수 있다.

- 단백질의 Chain ID가 누락되거나 중복되는 문제
- 서로 다른 단백질 사슬이 하나로 연결되는 문제
- 실제 단백질 서열과 PDB 파일의 잔기 번호가 일치하지 않는 문제
- 물 분자, 이온, 수소 원자 등이 포함되는 문제
- 표준 아미노산 명명 규칙과 다른 잔기 이름이 사용되는 문제
- 분석에 필요한 Mutation List를 수작업으로 생성해야 하는 문제

개별 파일이라면 직접 수정할 수도 있지만, 분석해야 할 구조의 수가 늘어날수록 전처리 작업에 많은 시간과 노력이 필요하다.

또한 수동으로 파일을 수정하는 과정에서 발생한 작은 오류가 이후 연구 결과의 해석에 영향을 줄 수 있다.

이러한 문제에서 프로젝트를 시작했다.

## Domain Knowledge

### PDB 파일이란?

PDB(Protein Data Bank) 파일은 단백질과 같은 생체 분자의 3차원 구조 정보를 저장하는 파일 형식이다.

각 원자의 종류와 소속 잔기, 단백질 사슬, 공간 좌표 등의 정보를 포함한다.

PDB 파일의 일부를 살펴보면 다음과 같다.

![](https://velog.velcdn.com/images/kjamm/post/a18a7258-ab53-4ca3-8f5b-3fa6f0acbb11/image.png)

각 레코드에는 다음과 같은 정보가 포함되어 있다.

- 원자 데이터 레코드
- 원자 이름
- 아미노산 종류
- 단백질 사슬 식별자
- 아미노산 잔기 번호
- 원자의 3차원 위치

PDB는 단순한 텍스트 파일처럼 보이지만, 각 정보가 지정된 열에 위치하는 Fixed-width Format을 사용한다.

따라서 데이터를 수정할 때는 문자열뿐만 아니라 각 필드의 위치와 길이까지 고려해야 한다.

### mCSM-PPI2와 ΔΔG

mCSM-PPI2는 단백질 구조를 기반으로 아미노산 변이에 따른 결합 친화도 변화를 예측하는 머신러닝 도구이다.

대표적인 예측 결과는 결합 자유에너지 변화량인 ΔΔG이다.

mCSM-PPI2의 부호 규약에서는 다음과 같이 해석할 수 있다.

- 음수 : 결합 친화도 감소 방향
- 0에 가까운 값 : 상대적으로 작은 변화
- 양수 : 결합 친화도 증가 방향

특정 잔기를 다른 아미노산으로 치환했을 때 결합 친화도가 크게 감소한다면, 해당 잔기를 결합에 중요한 Hotspot 후보로 고려할 수 있다.

이러한 분석을 수행하기 위한 입력 데이터를 생성하는 것이 pdb2mcsm의 역할이다.

![](https://velog.velcdn.com/images/kjamm/post/2b788143-b025-48df-9304-114593f39376/image.png)

구조 데이터와 머신러닝 기반 분석 도구 사이의 간극을 해결하는 Data Preprocessing Pipeline이다.

## 핵심 기능 및 기술적 구현

### Fixed-width PDB Parsing

PDB 파일을 처리하기 위해 먼저 각 원자 레코드에서 필요한 정보를 추출하는 파서를 구현했다.

PDB 파일은 필드의 위치가 고정되어 있기 때문에 일반적인 공백 기반 문자열 분리보다 인덱스 기반 파싱이 적합하다.

![](https://velog.velcdn.com/images/kjamm/post/d86ba854-6045-42b6-8cf9-74c79c0c190e/image.png)

이렇게 추출한 데이터를 Python의 dataclass를 활용하여 구조화했다.

프로젝트에서는 원자 수준의 정보를 관리하는 Atom과 단백질 사슬 수준의 정보를 관리하는 Chain 자료구조를 사용한다.

![](https://velog.velcdn.com/images/kjamm/post/2042aced-5db0-4670-959a-ec819856418f/image.png)

원본 텍스트와 구조화된 잔기 정보를 함께 관리함으로써 파일을 다시 출력하는 과정과 Mutation List를 생성하는 과정을 연결할 수 있도록 설계했다.

### Fallback 기반 Chain Detection 알고리즘

프로젝트에서 핵심적으로 고려한 문제는 단백질 사슬을 어떻게 구분할 것인가였다.

정상적인 PDB 파일에서는 Chain ID를 이용하여 서로 다른 단백질을 구분할 수 있다.

Protein A → Chain A
Protein B → Chain B

하지만 시뮬레이션 결과에 따라 Chain ID가 누락될 수도 있다.

이러한 상황을 처리하기 위해 세 단계의 우선순위를 갖는 규칙 기반 알고리즘을 적용했다.

![](https://velog.velcdn.com/images/kjamm/post/93c603c3-c928-4663-9730-08a22e69b191/image.png)

**Priority 1. Existing Chain ID**

기존 Chain ID 정보를 우선적으로 활용한다.
정상적으로 구분되어 있는 구조 데이터에서는 원래의 식별자를 최대한 유지하도록 했다.

**Priority 2. TER Record**

Chain ID가 없는 경우에는 단백질 사슬의 종료를 나타내는 TER 레코드를 활용한다.

![](https://velog.velcdn.com/images/kjamm/post/0de26675-814d-47f5-ab0d-cc79a9328f83/image.png)

**Priority 3. Residue Number Discontinuity**
앞선 두 방법을 적용할 수 없는 경우 잔기 번호의 불연속성을 기반으로 사슬의 경계를 추론한다.

![](https://velog.velcdn.com/images/kjamm/post/4e56b2cb-bb71-4765-9a1a-22ce8ec2d60e/image.png)

잔기 번호가 감소하거나 허용된 간격을 초과하는 경우 새로운 Chain의 후보 경계로 판단한다.

다만 잔기 번호의 불연속성은 서로 다른 단백질 사슬뿐만 아니라 실험 과정에서 관측되지 않은 잔기 때문에 발생할 수도 있다.

따라서 이 방식은 확정적인 분리 방법이 아닌 Heuristic Fallback으로 사용하고, 적용 시 사용자에게 경고를 제공하도록 설계했다.

### 비표준 아미노산 정규화

분자 동역학 시뮬레이션에서는 아미노산의 화학적 상태에 따라 일반적인 아미노산 명명 규칙과 다른 이름을 사용하기도 한다.

대표적인 예시는 다음과 같다.

![](https://velog.velcdn.com/images/kjamm/post/43b42419-1c3d-48b3-81e2-cc4a8e9c21e1/image.png)

이를 처리하기 위해 Dictionary 기반의 데이터 매핑을 적용했다.

새로운 비표준 잔기를 지원해야 하는 경우 매핑 테이블을 확장하는 방식으로 대응할 수 있다.

인산화된 아미노산은 표준 잔기로 변환하면서 관련 인산기 원자도 제거한다.

다만 이러한 처리는 원래의 화학적 상태를 보존하는 것이 아니다. 분석 목적에 따라 변환으로 인한 생물학적 의미의 손실을 고려해야 한다.

### 불필요한 구조 데이터 제거

원본 PDB 파일에는 단백질 이외에도 다양한 분자가 포함될 수 있다.

- Water molecules
- Ions
- Hydrogen atoms
- Common crystallization additives

분석 도구의 입력 요구사항에 맞도록 정의된 제거 대상 목록과 원소 정보를 이용하여 해당 데이터를 필터링한다.

수소 원자의 경우 PDB의 Element 필드를 우선적으로 확인하고, 해당 정보가 없다면 Atom Name을 이용해 판별한다.

다만 금속 이온이나 보조인자가 단백질의 기능과 결합에 직접적으로 관여할 수 있으므로, 모든 연구 목적에 적합한 전처리 방식은 아니다.

### Residue Renumbering

단백질 구조 연구에서는 논문에서 사용하는 잔기 번호와 실제 모델 파일의 잔기 번호가 서로 다른 경우가 있다.

예를 들어 절단된 단백질 구조가 다음과 같이 저장될 수 있다.

![](https://velog.velcdn.com/images/kjamm/post/5dcc94dd-dac2-49a1-afe1-468acdfc5122/image.png)

이를 해결하기 위해 특정 Chain의 잔기 번호에 일정한 Offset을 적용하는 기능을 구현했다.

![](https://velog.velcdn.com/images/kjamm/post/160a8781-bf21-4171-a1c0-a818f9031b18/image.png)

![](https://velog.velcdn.com/images/kjamm/post/9b43c5fa-beb9-4744-8f7c-bbb87aa21895/image.png)

여기서 중요한 부분은 단순히 PDB 파일의 숫자만 수정하는 것이 아니라는 점이다.

원자 레코드와 내부 잔기 목록의 번호를 모두 수정해야 이후 Mutation List를 생성할 때 데이터 불일치가 발생하지 않는다.

![](https://velog.velcdn.com/images/kjamm/post/7ec13075-e66e-4060-9b36-f6b88bac3311/image.png)

또한 100A, 100B와 같은 PDB Insertion Code를 구조 데이터 내에서 유지하도록 했다.

이를 통해 원본 구조와 이후 분석 데이터 간의 일관성을 고려했다.

### Alanine Scanning Mutation List 자동 생성

Alanine Scanning은 단백질의 특정 아미노산을 Alanine으로 치환하여 해당 잔기가 구조나 결합에 미치는 영향을 확인하는 분석 방법이다.

여러 잔기를 분석해야 하는 경우에는 Mutation List를 직접 생성하는 작업이 필요하다.

pdb2mcsm에서는 지정한 Chain과 잔기 범위를 기반으로 변이 목록을 자동 생성한다.

![](https://velog.velcdn.com/images/kjamm/post/c9a96bb0-7ecb-42c0-a52f-5b353e271c2e/image.png)

출력 예시는 다음과 같다.

![](https://velog.velcdn.com/images/kjamm/post/6e8a4d13-9bdb-44f5-a300-31d4d2496a55/image.png)

이미 Alanine인 잔기에 대해서는 Glycine으로 치환하는 별도의 규칙을 적용했다.

이는 일반적인 Alanine Scanning과는 구분되는 예외 처리이다.

이러한 기능을 통해 전처리된 구조 파일뿐만 아니라 후속 분석에 필요한 입력 데이터까지 하나의 파이프라인에서 생성할 수 있도록 했다.

## 데이터 신뢰성을 고려한 설계

생명정보학 연구에서 데이터 전처리 도구를 개발할 때 중요한 것은 단순히 코드가 정상적으로 실행되는 것만은 아니다.

잘못된 입력 데이터가 정상적으로 처리된 것처럼 보이는 Silent Failure가 더 큰 문제가 될 수 있다.

예를 들어 하나의 단백질 사슬을 두 개의 사슬로 잘못 분리하더라도 출력 파일 자체는 생성될 수 있다.

하지만 이후 수행되는 단백질 상호작용 분석은 잘못된 구조 정보를 기반으로 이루어지게 된다.

이러한 문제를 줄이기 위해 pdb2mcsm은 다음과 같은 검토 정보를 제공한다.

- Chain 분리에 사용된 방법
- Chain별 아미노산 잔기 수
- 시작 및 종료 잔기
- 추론 기반 Chain 분리 시 경고
-하나의 Chain만 감지된 경우 경고

![](https://velog.velcdn.com/images/kjamm/post/f665b557-95d0-4553-bdb4-0f160568462e/image.png)

위 표는 구조 요약 정보의 예시이다.

프로그램이 판단하기 어려운 상황에서는 무조건 자동 처리를 신뢰하기보다 사용자가 중간 결과를 검토하도록 유도하는 방식을 선택했다.

## 사용자 접근성 개선 - Google Colab

생명과학 분야의 모든 연구자가 Python이나 개발 환경에 익숙한 것은 아니다.

따라서 코드를 GitHub에 공개하는 것에서 끝내지 않고 Google Colab에서도 실행할 수 있도록 구성했다.

사용자는 별도의 개발 환경 구축 없이 다음과 같은 흐름으로 프로젝트를 활용할 수 있다.

![](https://velog.velcdn.com/images/kjamm/post/d1e3f871-9edc-44d7-92eb-c2f4587d2f8a/image.png)

이를 통해 프로그래밍 경험이 없는 사용자도 자신의 연구에 활용할 수 있도록 접근성을 높이고자 했다.

## 프로젝트를 통해 해결한 문제

프로젝트를 통해 여러 단계로 분산되어 있던 구조 데이터 전처리 작업을 하나의 파이프라인으로 통합했다.

이를 통해 반복 작업을 줄이고, 동일한 전처리 규칙을 여러 구조 데이터에 적용할 수 있는 기반을 마련했다.

## 프로젝트의 한계 및 향후 개선 방향

현재 프로젝트는 구조 데이터의 형식과 호환성을 개선하는 데 초점을 맞추고 있다.

따라서 모든 구조적, 생물학적 문제를 해결할 수 있는 것은 아니다.

현재 한계

- 잔기 번호의 Offset을 자동으로 탐색하지 않는다.
- 추론에 기반한 Chain 분리는 사용자 검증이 필요하다.
- 결손 원자나 구조적 충돌을 복구하지 않는다.
- 모든 종류의 비표준 아미노산을 지원하지 않는다.
- 인산화 잔기의 변환 과정에서 원래의 화학적 정보가 손실된다.
- Insertion Code가 있는 잔기의 Mutation List 생성에는 추가 검증이 필요하다.

향후 개선 방향

1. Sequence Alignment 기반 Residue Mapping

고정 Offset 방식에서 벗어나 실제 단백질 서열과 구조 서열 간의 정렬을 통해 잔기 번호를 자동으로 매핑하는 기능을 개발하고자 한다.

이를 통해 중간 잔기가 누락된 구조나 복잡한 번호 체계도 처리할 수 있을 것이다.

2. 구조적 정보를 활용한 Chain Detection

잔기 번호뿐만 아니라 원자 간 거리와 단백질 Backbone의 연결성 등을 함께 고려하여 Chain 분리 알고리즘을 개선할 수 있다.

3. Batch Processing 및 자동화된 테스트

다수의 PDB 파일을 일괄 처리하고 다양한 구조 데이터와 예외 상황을 대상으로 자동화된 테스트를 확장하고자 한다.

4. Hotspot Analysis Pipeline 구축

향후에는 PDB 전처리뿐만 아니라 예측 결과 분석까지 연결하는 통합 파이프라인으로 확장하고자 한다.

![](https://velog.velcdn.com/images/kjamm/post/073d3cdd-27cb-4c74-85b3-1937f945013b/image.png)

mCSM-PPI2, FoldX, ConSurf 등 다양한 분석 도구와의 연계를 통해 단백질 결합 부위 분석 및 펩타이드 설계에 활용할 수 있는 연구 파이프라인으로 발전시키는 것이 목표이다.

## 프로젝트를 진행하며 배운점

이번 프로젝트는 생명과학 연구에서 발생하는 문제를 컴퓨터 과학적인 방식으로 해결하는 경험이었다.

처음에는 PDB 파일을 분석 도구에서 사용할 수 있도록 수정하는 문제에서 출발했지만, 이를 일반화하는 과정에서는 다양한 기술적 요소를 고려해야 했다.

- 도메인 지식을 활용한 문제 정의
- 비정형 구조 데이터의 파싱 및 구조화
- 규칙 기반 알고리즘 설계
- 예외 상황에 대한 Fallback 전략
- 데이터 일관성 및 신뢰성 관리
- 모듈화와 코드 재사용성
- 사용자 중심의 인터페이스 설계
- 오픈소스 프로젝트 문서화

특히 머신러닝 모델을 활용하는 연구에서 모델의 예측 성능뿐만 아니라, 모델에 전달되는 입력 데이터의 품질 역시 중요하다는 점을 배울 수 있었다.

아무리 좋은 예측 모델을 사용하더라도 입력 데이터가 잘못되었다면 신뢰할 수 있는 결과를 얻기 어렵기 때문이다.

## 마치며

생명과학을 공부하면서 머신러닝과 컴퓨터 과학에 관심을 갖게 되었고, 두 분야를 연결하여 실제 연구 문제를 해결하는 프로젝트를 진행하고자 했다.

pdb2mcsm은 그러한 관심에서 출발한 프로젝트이다.

단순히 기존 분석 도구를 사용하는 것에서 나아가, 기존 도구의 활용 과정에서 발생하는 문제를 발견하고 이를 직접 해결하는 소프트웨어를 개발했다는 점에서 의미가 있다.

앞으로는 데이터 전처리뿐만 아니라 단백질 구조와 결합 친화도를 분석하는 머신러닝 모델 자체를 설계하고 개발하는 방향으로 프로젝트를 확장하고자 한다.

생명과학적 문제를 컴퓨터 과학적으로 정의하고, 이를 알고리즘과 소프트웨어로 해결하는 것.

이것이 pdb2mcsm을 통해 추구한 방향이다.
